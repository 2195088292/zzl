# AI 知识库 V6.5 第二阶段

本版增加知识库独立配置、混合检索、索引任务追踪和检索测试。入口仍为左侧菜单的“知识库”。

## 使用

1. 新建或打开知识库，在“配置”中设置分块、召回和向量模型。
2. 初次使用可以保留“跟随系统配置”。需要语义检索时，为知识库选择 Ollama 或 OpenAI 兼容的 Embedding 服务，并填写实际向量模型名称。聊天模型与向量模型分别配置。
3. 修改分块大小、重叠长度、向量服务地址或模型名称后，点击“保存并重建”。只点击“保存配置”会保留原索引，文档显示“待重建”。Top-K、阈值和精确匹配重排保存后立即生效。
4. 上传文件后，在文档列表查看排队、进度、失败和暂停状态。点击文件名查看任务详情。暂停后的“恢复”会重新索引这个文件。
5. 在“检索测试”输入真实问题、错误码或模型名称，查看召回片段、候选数、名次、向量得分和耗时；点击“查看原文”核对上下文。
6. 在 AI 工作台选择知识库提问。执行面板展示本次检索信息，引用随回答一起保存，刷新后仍可查看来源。

## 配置范围

| 配置 | 范围或行为 |
| --- | --- |
| 分块大小 | 300–8000 字符，默认 1200 |
| 重叠长度 | 0 到分块大小的一半，默认 180 |
| Top-K | 1–20，默认 6 |
| 向量相似度阈值 | 0–1，默认 0.10；只约束向量召回 |
| 精确匹配重排 | 默认开启，强化完整名称、错误码和原句匹配 |
| 向量服务 | 系统配置、本地词法向量、Ollama、OpenAI 兼容接口 |

API Key 保存后不返回原值。编辑时留空保留原密钥。当前界面没有单独清空密钥按钮。

## 数据与检索

- MySQL 保存知识库配置、文件关系、附件元数据、切片、向量 JSON、索引任务和索引配置版本。原文件保存在 `zzl.profile/ai-files/`。Redis 不承担知识库的唯一持久化职责。
- 关键词候选使用 MySQL FULLTEXT，并保留精确匹配与中文重叠二元词法召回。全文索引不可用时，词法召回仍可工作；当前默认 FULLTEXT 使用普通解析器，未启用 ngram 插件。
- 向量候选使用当前知识库的 Embedding 模型。Qdrant 为可选加速存储，不可用时读取 MySQL 中相同模型的向量。远程 Embedding 调用失败时，检索退回关键词并返回提示；重建失败时保留原有 MySQL 索引。
- 采用 RRF 合并关键词和向量名次，再执行可关闭的规则重排与正文去重。不同知识库的向量分别排序，避免直接比较不同模型的余弦分数。
- 每个知识库与向量模型采用独立 Qdrant 集合。更换模型后必须重建；旧集合的空间回收暂未提供管理页面。
- 工作台同时选择多个知识库时，各库使用自己的向量模型和阈值；最终返回数量取已选知识库 Top-K 的最大值。

“本地词法向量”是基础哈希特征，不等同于训练好的语义 Embedding。当前重排也是规则重排，没有接入独立的神经重排序模型或 LLM 查询改写。

## 文件与 OCR

新增 PPTX 文本提取。PDF 提取保留页码标记，PPTX 提取保留幻灯片标记；来源预览仍以切片和字符范围定位。

OCR 为可选接入，默认关闭。安装 Tesseract 和所需语言包后，在 `application.yml` 中启用：

```yaml
zzl:
  ai:
    rag:
      ocr:
        enabled: true
        command: tesseract
        languages: chi_sim+eng
```

扫描 PDF 最多对前 30 页执行 OCR。单次 OCR 超时 45 秒。图片未识别出文本时不会建立文本索引，但仍可交给支持视觉的聊天模型分析。

当前文件提取上限为 120000 字符，单文件最多 1000 片段；本地检索扫描上限为 5000 片段，并补充 FULLTEXT 和外部向量候选。大规模知识库应继续升级分页候选与批量向量写入。

## 数据库升级

应用启动时，`AiConversationSchemaInitializer` 为现有表补充分块配置、Embedding 配置、任务进度、阶段和索引版本字段，并尝试创建全文索引。首次建库脚本为 `sql/zzl_ai_agent_v6.sql`。已有数据无需清空；旧文档完成一次重建后会记录新版本。

## 本次验证

- 14 项测试通过，覆盖词法召回、中文分词、去重、Top-K、向量生成失败保留旧索引、跨模型空间排名、暂停恢复、Qdrant 两种响应格式和 Embedding 请求协议。
- 独立测试作用域完成真实 MySQL 的创建、配置、上传、异步索引、检索、隔离、停用、删除和附件重新加载；测试数据已清理。
- 前端生产构建通过。Playwright 使用真实页面组件与模拟接口检查配置保存、检索、原文预览和布局；这不是连接真实聊天模型的端到端测试。
- 当前机器未运行 Qdrant、Ollama 或 Tesseract，相关连接使用协议测试验证，尚未做实际服务联调。
